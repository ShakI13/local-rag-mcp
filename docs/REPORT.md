## First-run

1. Агент собрал гибридный поиск по спеке. Автотесты прошли (**19**).
2. Живая сборка индекса упала: ошибка при загрузке документов (см. баг 1).
3. Живой чат тоже упал: локальная модель `qwen3:0.6b` не была установлена (см. баг 2).
4. Дальше чинили уже качество ответов (eval, вызов файловых тулов, вопросы «что ты умеешь»). Финальный лог прогона в репозиторий не клали.

## Уточняющие вопросы

До кода агент спросил, на что оптимизируем домашку, как смешать поиск по смыслу и по словам, и нужно ли лучше понимать русский. Договорились: закрыть критерии оценки и чуть улучшить русский поиск; файловые MCP-тулы не трогать.

Два раза первый ответ пользователя конфликтовал с «не раздувать объём» (два поисковых движка сразу; морфология). Агент переспросил, затем DoD расширили осознанно. Вопросы по делу, без воды. Тексты: `docs/extra_prompts.md`.

## Баги

1. **Сборка индекса.** Загрузка документов вызывала саму себя с путём к файлу и падала. Фикс: убрать лишний вызов, дерево и так обходится.
2. **Чат после индекса.** Ollama ответила «модель не найдена», а код ждал поле с текстом ответа и падал. Фикс: взять установленную `qwen3:1.7b` и показывать ошибку API, а не `KeyError`.
3. **Правильные куски, пустой ответ.** Поиск нашёл asyncpg и миграции, но модель вызвала чтение несуществующего `docs/asyncpg.md`, в промпт попал служебный JSON, ассистент сказал «нет информации». Фикс: не подставлять сломанный ответ тула; путь к файлу брать из найденных источников.
4. **«О чём у тебя есть инфа?» / «Как тобой пользоваться?»** На общие вопросы система отвечала отказом. Фикс: короткий обзор базы знаний; список документов не должен вести к отказу.
